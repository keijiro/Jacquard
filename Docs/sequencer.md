# シーケンサ仕様メモ

`mockup.html` はシーケンス画面のモックアップである。静的な見た目のみを実装しており、
音を出す機能も編集機能も持たない。このメモはコードを読んでも分からない部分、
つまり各要素が何を意味するのか、なぜその形なのか、何がまだ決まっていないのかを
補うためのものである。

## 用語

コード内のシンボル名として使う語を以下に固定する。

| 語 | 指すもの |
| --- | --- |
| `Project` | ファイル保存の単位。`Score` の上位 |
| `Score` | 1 枚のグリッド平面 |
| `Cell` | グリッド上のマス。何も置かれていない位置も含む |
| `Lane` | 横方向に伸びるステップの列 |
| `Step` | レーン内の 1 列 |
| `Stack` | ステップから下へ伸びるタイルの連なり。長さに制限はない |
| `Rail` | レーンを貫く時間軸の点線 |
| `Link` | `JUMP` から `JDST` への接続 |
| `Tile` | セルに置かれる機能単位。1 セルにつき 1 個 |
| `NoteTile` | 発音するもの |
| `ParamTile` | 音の属性を操作するもの（`PABS` / `PREL`） |
| `GateTile` | 以降を処理するかどうかを決めるもの（`GCYC` / `GPRB`） |
| `FlowTile` | シーケンスの流れを制御するもの（`CHAN` / `TERM` / `JUMP` / `JDST`） |
| `Runner` | レーンを走査してタイルを実行する動的オブジェクト。再生時にのみ存在する |

`Project` 以下はすべて静的なデータだが、`Runner` だけは再生時に生まれて動く。

具象のタイル型とトークンの対応は以下の通り。

| トークン | 型名 |
| --- | --- |
| （音名） | `NoteTile` |
| `PABS` | `AbsoluteParamTile` |
| `PREL` | `RelativeParamTile` |
| `GCYC` | `CycleGateTile` |
| `GPRB` | `ProbGateTile` |
| `CHAN` | `ChannelTile` |
| `TERM` | `TerminatorTile` |
| `JUMP` | `JumpTile` |
| `JDST` | `JumpDestTile` |

具象名にカテゴリ語（`Param` / `Gate`）を入れるのは、**修飾語だけでは意味が
通らない場合に限る**。`Absolute` や `Cycle` は単独では何のことか分からないので
カテゴリ語が要るが、`Jump` / `Terminator` / `Channel` は単独で通じるので
`JumpFlowTile` のようには書かない。所属は型階層が示すので、名前で重ねない。

### `Project` と `Score`

`Score` は 1 枚の平面である。複数チャンネルを扱うようになっても**同一平面上に
並べる**方針なので、チャンネルごとに平面を分けることはしない。

`Project` はその上位にあり、**ファイル保存の単位**である。全体に掛かる設定を
持ち、現在のところ **テンポと拍子** がここに属する。

現時点で `Project` が持つ `Score` は 1 枚だけである。将来的に複数の `Score` を
束ねる構想はあるが、**束ねる必然性をまだ見出していない**。したがって今は
「`Score` より上位にあって保存単位になるもの」以上の意味を `Project` に
持たせない。複数枚を扱う理由が見つかった時点で定義を足す。

タイルの分類は 4 つだが、見た目は 3 つしかない（`ParamTile` と `GateTile` が
どちらも灰色背景で、アイコンの絵柄でしか区別できない）。**このずれは把握済みで、
将来は見た目の側を調整して解消する。** 分類を 3 つに減らす方向では解決しない。

## 基本モデル

グリッドは 1 枚の平面で、そこに **レーン** を置く。レーンは横方向に伸びる
ステップの列で、**横軸が時間**、1 列が 1 ステップに対応する。

**レーンは平面上のどこにでも自由に置ける。** これはこのシーケンサの中核的な性格
であって、置き場所の制約が無いことに意味がある。別チャンネルのレーンも、同じ
チャンネルの並走レーンも、分岐先のレーンも、配置規則で区別しない。**何のレーンか
は先頭セルが示すのであって、位置は示さない。**

ただし位置がまったく無意味なわけではない。**`CHAN` タイルの縦位置は Runner の
実行順を決める**（「Runner」を参照）。種類は位置で決まらないが、優先順位は
位置で決まる、という切り分けである。

開始位置はグリッド座標で持ち、レーン同士が同じセルを占めることはない。

**レーンの性格は先頭セルの種類で決まる。**

- `CHAN` が先頭 → そのチャンネルの**独立した流れ**。他の `CHAN` レーンと同時に走る
- `JDST` が先頭 → **分岐先**。`JUMP` から入るときにしか通らない

現在のモックアップには 3 本のレーンがあり、上から順にこう並んでいる。

- アクセントレーン — 4 ステップ。先頭 `CHAN:1`。ノートを持たず、下のレーンに掛かる
- メインレーン — 16 ステップ。先頭 `CHAN:1`。アクセントレーンと同時に走る
- バリエーションレーン — 6 ステップ。先頭 `JDST`。メインレーンから飛んでくる

この上下関係には意味がある（「Runner」を参照）。

1 ステップは **同時に起こる事柄を縦に積む**。和音の構成音も、そのステップに掛かる
制御要素も、すべてこの縦のスタックに入る。

**スタックの長さに制限はない。** 平面の余白が許す限りいくらでもタイルをぶら下げ
られる。かつては「1 ステップあたり最大 4 スロット」という枠を設けていたが、
枠の数を決める根拠が無く、レーンごとに必要な深さも違ったので廃止した。
「スロット」という概念自体を捨て、**ステップが持つのは長さ可変のタイルの列**
だと考える。

したがってレーンが占める領域は矩形ではない。実際に埋まっているセルだけが
そのレーンのものである。

### 縦チェーンの規則 — 処理は上から下へ流れる

縦に隣接するセルは 1px の実線で繋がれ、ひとつの塊として読ませる。
この連結には向きの意味がある。

**スタックは上から順に処理され、あるタイルの効果はそれより下にしか及ばない。**

- `GCYC` / `GPRB`（発火条件）— 成立すればそのまま下へ進み、成立しなければ
  **そこで処理を打ち切る**。上にあるものは既に処理を終えているので影響を受けない
- `PABS` / `PREL`（パラメーターロック）— **それ以降に鳴る音**に掛かる。
  直下の 1 つではなく、下にあるノートすべてである。上にあるノートには掛からない
- ノート — その深さにおけるパラメーターの状態で発音する

したがってスタックは上から順に **発火条件 → パラメーター → ノート** の並びになる。
掛けたいもの・制御したいものより**先に**書く、というのが唯一の規則である。

かつては「上のセルが下のセルを従える」という支配・従属の関係で説明していた。
`GCYC / A4` は上の条件が下のノートを制御し、`A4 / PABS` は下のロックが上のノートに
付随する、というふうに、**互いに逆向きの読み方が同居していた**。連結線はすべて
同一の 1px 線なので、`GPRB:4 / A4 / PABS` のような列を見たときどちらの向きに
結合しているかはトークンの種類を知らないと読めない、という弱点があった。

**一方向の流れに改めたことでこの弱点は消えた。** 線は常に上から下へ読めばよく、
種類を知らなくても効果の向きは分かる。制御要素の背景を灰色にしているのは、
いまは種類の判別を助けるためだけの意匠である。

この規則は、種類ごとに並べたスタックだけでなく**混在したスタックにも同じように
効く**。たとえば `E4 / GCYC4:1 / C4` と書いた場合、

- `E4` はゲートより上にあるので**毎周鳴る**
- `C4` はゲートより下にあるので**4 周に 1 回鳴る**

となる。旧規則ではステップ内のゲートがステップ全体に掛かったので、この譜面では
両方が 4 周に 1 回になっていた。**ゲートの上に置いたものは、そのゲートに影響され
ない**——これが変更のいちばん目に見える帰結である。

帰結として、**レール行（深さ 0）に置いたタイルは、そのスタックの中では
何にも従わない。** その上に何も置けないので、条件を付けることもロックを
掛けることもできない。`JUMP` について既に述べていた制約が、ノートにも
ロックにも同じように及ぶ。レール行のノートを条件付きにしたいなら、
条件をレール行に置いてノートを 1 つ下げる。

### レールと端点

各レーンは点線が水平に貫く。これがそのレーンの時間軸で、両端を白塗り潰しの
セルが挟む。

**単純に右へ進む以外の挙動をする端点は、すべて白塗り潰しのセルとする。**
これを規則とした。現在 4 種類ある。

| トークン | アイコン | 挙動 |
| --- | --- | --- |
| `CHAN:n` | テキスト（`CH1` と表示） | チャンネル n のシーケンス開始点 |
| `TERM` | 左へ U ターンする矢印 | 終端。開始元の `CHAN` へ戻る |
| `JUMP` | 角の丸い Z 字＋右矢印 | 別レーンへ飛ぶ |
| `JDST` | 縦線＋右矢印 | 飛び先。レーンの開始 |

`TERM` は最終ステップの右隣に自動的に置かれる。かつて点線レールは「最後の ▶
マーカー」を終点にしていたが、これは最終ステップの最上段にノートが入ると
レールが手前で切れる実装だった。終端を暗黙に推測させず、明示的なセルとして
持たせることで解消している。

**`TERM` に到達すると、開始元の `CHAN` へ戻る。** これはどのレーンの `TERM` でも
同じで、バリエーションレーンの `TERM` も自分のレーンの先頭（`JDST`）ではなく
チャンネルの開始点へ戻る。つまり `JDST` は `JUMP` から入るときにしか通らない。

`▶` マーカーは、そのステップのスタックが空のときに現れる。
結果として ▶ は「何も置かれていない拍」だけに並び、素通りする区間の目印として働く。
これは意図して設計したものではなく実装から生じた振る舞いだが、
読みやすさに寄与しているため現状維持としている。

### 3 種類の線

線の種類が意味を担っている。

| 見た目 | 意味 |
| --- | --- |
| 1px 白の実線（縦） | 同一ステップ内のスタックを繋ぐ。上から下へ読む |
| 2px 白の点線（横） | レーンの時間軸。左から右へ流れる |
| 1px 灰の実線（角丸、軸をずらす） | レーンをまたぐジャンプの経路 |

ジャンプの線だけはセル中心を通らず、列中心の右 7.5px / 行中心の下 7.5px を通る。
格子の `・` を潰さずに横断させるためで、結果としてレールとは別のレイヤに乗って
いるように読める。

`JUMP` のセルは、この 3 種類のうち 2 種類が出会う唯一の場所である。上からは
スタックを降りてくる白実線が、下へは灰の実線（時間的な飛び先）が伸びる。

## 詳細設定は別ウィンドウで

タイルはセルに描かれる以上の情報を持つ。**タイルを選択すると別ウィンドウが開き、
そこで詳しく設定する。** グリッド上のセルはタイルの種別と、譜面を読むうえで
欠かせない値だけを示せばよく、設定のすべてを 30px の中に詰め込む必要はない。

この方針で解決した項目。

- **パラメーターロックが掛ける対象と変化量** — タイル上には出さない。`PABS` / `PREL`
  のアイコンは「どの種類のロックか」だけを示し、どれをいくつ動かすかは
  別ウィンドウで設定する。対象は複数あり得るので、そもそもセルには入らない
- **1 ステップの実時間の長さ** — `CHAN` タイルのオプション。既定は 16 分音符
- **`GPRB` の確率** — 任意の float をパーセントで指定する
- **`GCYC` の周期** — 2 〜 8 の範囲で指定する

後ろの 2 つは値をアイコンの形そのもので表しているため、**セル上には概形が出る**。
正確な値の入力はダイアログで行い、セルはそれを図として見せる、という分担になる。

したがって**トークン文字列はデータそのものではなく、表示のための符号**である。
`CHAN:1` の引数はチャンネル番号だけで、ステップ長はトークンに現れない。

## トークン

タイルの種別を表すトークンは **4 文字に揃える**。将来 FourCC としてそのまま
扱える余地を残すためである。引数を取るものは `GCYC4:3` / `GPRB:4` のように
数字やコロンを後置するが、種別を表す部分は 4 文字である。

接頭辞はカテゴリを表す。`P` がパラメーター（`PABS` / `PREL`）、
`G` がゲート（`GCYC` / `GPRB`）。型名の規則と同じく、**修飾語だけでは曖昧な
ものにだけ接頭辞を付ける**ので、`JUMP` / `JDST` / `TERM` / `CHAN` には付かない。

かつて確率ゲートは `PROB` で、パラメーターの `P` と接頭辞が衝突していた。
また周回ゲートは `NGTE`（note gate）で、`JUMP` もゲートできる以上「note」が
実態と合わなくなっていた。両者を `GPRB` / `GCYC` に改めて解消している。

かつてチャンネルの開始点だけが `CH1` という 3 文字で、種別名とチャンネル番号が
一体になっていた。これを `CHAN:1` に改め、種別と引数を分離した。
現在すべての種別トークンが 4 文字である。

### ノート

`C4` / `F#4` / `G#4` のように音名＋オクターブで書く。臨時記号はセル内で
上付き表示になる。

**長さの単位はステップで、既定は 1 ステップ。** 既定のままなら音名だけを
表示し、それ以外の長さを設定したときだけ `C4/4` のように数値を添える。
セル内では音名の下に小さく出る。`0.5` のような 1 未満も書ける。

1 ステップを何分音符とするかは `CHAN` タイルのオプションで、既定は 16 分音符。
その音符が実時間で何秒かはテンポ次第で、テンポと拍子は `Project` が持つ。
つまり既定の組み合わせでは、数値の付かないノートが 16 分音符 1 つ分になる。

**半音は ♯ のみで表す。♭ は廃止した。** 同じ音を 2 通りに書けると、
グリッド上で同じセルが違う見た目になってしまうため、表記を 1 つに固定した。
`G#4` を `Ab4` と書くことはできない。

### パラメーターロック

パラメーターを操作する。**1 個のロックは複数のパラメーターを同時に掛けられる。**
対象ごとにスロットを持ち、値を与えたものだけを掛ける。掛けていないパラメーターには
何も起こらず、チャンネルの持つ値がそのまま通る。

かつては 1 個のロックが 1 個の対象しか持てなかった。4 つのパラメーターを動かすには
ロックタイルを 4 枚縦に積むしかなく、ゲートと音符の間が間延びして、和音の途中に
境目を作る余地も食い潰していた。**積み重ねで表現できることは何も無かった**ので、
1 枚に畳んだ。

**何も掛けていないロックを許容する。** 置いた直後のロックがこれで、何も起こさない。
「行き場のないロックは無意味なタイルになる」のと同じ扱いで、鳴らないだけで害が無い。

掛かる範囲には 2 つの縛りがある。

- **常にチャンネル全体に掛かる。** ノート個別の属性ではない
- **そのステップ限りである。** 次のステップには何も残らない。チャンネルは
  毎瞬、自分のパッチから始まる

この 2 つを合わせると、ロックが実際に色を付けるのは「同じ瞬間に、それより後に
処理されるもの」になる。**後**がどこまでを指すかは置いた場所が決める。同じ
スタックの下にあるノートと、平面上でより下にあるレーンが同じ瞬間に鳴らす音である。
したがって**ロックは掛けたい音より上に置く**。

- **ノートの上に置く** → その下のノートに掛かる
- **和音の途中に置く** → 境目より下の構成音だけに掛かる
- **ノートを持たないレーンに単独で置く** → 下のレーンが同じ瞬間に鳴らす音に掛かる。
  アクセントレーンの用法である（「並走レーン」を参照）

**行き場のないロックは無意味なタイルになる。** 一番下のレーンの一番下に置いた
`PABS` は、それ以降に処理されるものが何も無いので何も起こさない。
**この状態は許容し、エラーとして扱わない。** どの `CHAN` からも到達できない
`JDST` の輪と同じ扱いで、鳴らないだけで害が無い。

アイコンはいずれもフェーダーを基本形とし、右側の修飾子で種類を分ける。

| トークン | アイコン | 意味 |
| --- | --- | --- |
| `PABS` | フェーダー単体 | 絶対値でパラメーターを設定する |
| `PREL` | フェーダー＋ ↕ | 現在の値からの相対量で変更する |

かつて `PACC` という 3 つ目のロックがあり、相対的な変更を永続的に適用して、
パラメーターを上げ続ける／下げ続けるといった用途に使えた。**これを廃止した。**
ロックの影響が現在ステップの外に残ると、いま鳴っている音がどういう状態なのかを
譜面から読み取れなくなる。「ロックはそのステップ限り」という縛りを明確にする
ことを選び、その代償として `PACC` を捨てた。

**どのパラメーターを対象とするのかは、ここでは決めない。** 音源部分は別プロジェクト
として分離開発しており、対象パラメーターの集合は音源側が持つ。両者を結合する
段階で確定する事項であって、シーケンサ側の未決事項ではない。

**対象と変化量はセル上に表示しない。** アイコンは「どの種類のロックか」だけを
示し、詳細はタイルを選択して別ウィンドウで設定する。30px のセルに対象名と値を
詰め込む必要はない。1 個のロックが複数の対象を持てる以上、そもそも入らない。

**別ウィンドウには対象の全てを並べ、掛けていないものは薄く表示する。** バーを
動かせばそのパラメーターを掛けたことになり、名前をクリックすれば手を放す。
「掛ける」という操作を値の入力と別に用意しないのは、**誰も設定していない値は
ロックではない**からで、薄い行はそのまま「このタイルが手を出していない範囲」を
示す。薄い行が読み出す値は、掛けなかった場合にそのチャンネルがどうなるか
（`PABS` なら現在のパッチの値、`PREL` なら 0）である。

### 発火条件

スタックの処理を続けるかどうかを決める。**成立すればそのまま下へ進み、成立しな
ければそこで打ち切る。** 支配するのは直下の 1 つではなくそれより下のすべてで、
ノートもロックも `JUMP` も止まる。

1 つのスタックに複数置くと、下のものは上のものが通ったときにしか判定されない。
入れ子の条件になる。

| トークン | アイコン | 意味 |
| --- | --- | --- |
| `GCYCn:m` | n 個の矩形、m 番目が塗り | ループの特定の周のみ発火する。`GCYC4:3` は 4 周のうち 3 周目 |
| `GPRB:n` | 円グラフ | n パーセントの確率でランダムに発火する |

**`GCYC` の周期は 2 〜 8。** 矩形の列がセル幅に収まる限界がこの範囲である。
n が増えると矩形は細くなり、n=7 以上では矩形どうしの間隔も 1px に詰まる。
その状態でも「どれが塗られているか」は読める——塗りと中空の対比は、
太い細いの対比より強いためで、幅を変える方式より優先した。

**`GPRB` は任意の float をパーセントで取る。** 円グラフはその割合を扇形で示す。
かつて 12 分割の時計として扱っていたが、これは時計状のアイコンが描きやすい
分割数だったというだけで、確率の粒度を 12 段階に縛る理由は無かった。

## 分岐シーケンス

`JUMP` セルに到達すると、次のステップは自分のレーンの右隣ではなく、
接続先レーンの先頭になる。接続先は必ず `JDST` セルである。

`JUMP` は**単体ではほぼ意味を持たない**。無条件に飛ぶだけなら、
2 本のレーンを 1 本に繋いで書くのと変わらない。

意味を持つのは **発火条件と組み合わせたとき**である。`JUMP` の上に条件を置くと、
条件が成立した周だけ飛び、成立しなければそのまま自分のレーンを右へ進む。

- `GCYC` と組み合わせる → 定期的にシーケンスを別のバリエーションへ変化させる
- `GPRB` と組み合わせる → ランダムにシーケンスを変化させる

モックアップでは `GCYC4:4` ＋ `JUMP` を 10 番目のステップに置いている。
4 周に 1 回だけ、そこからバリエーションレーンの 6 ステップへ飛び、その `TERM` で
`CHAN:1` へ戻る。メイン 10 ステップ ＋ バリエーション 6 ステップ = 16 ステップと
なり、飛んでも飛ばなくても 1 周の長さが変わらないよう置いた。

条件を付けるためには `JUMP` がスタックの 2 段目以降に来る必要がある
（1 段目はレール行で、その上に条件を置けない）。したがって **`JUMP` を
レール行に直接置くと、条件を付けられない = 無条件ジャンプにしかならない。**

**`JUMP` に到達しても、そのスタックの処理はそこで終わらない。** 行き先が決まる
だけで、下に続くタイルは同じ瞬間のものとして処理される。飛ぶのはあくまで
**次の**ステップからである。1 つのスタックに到達可能な `JUMP` が 2 つあった場合は、
下にあるものが行き先になる。

### `JUMP` と `JDST` は 1 対 1

**`JUMP` が 1 つあれば、それに対応する `JDST` がちょうど 1 つ存在する。**
逆も同じで、どこからも飛ばれない `JDST` は存在しない。2 つの `JUMP` が
同じ `JDST` を指すこともできない。

この制約のうえで、次の 2 つは許す。

- **多段分岐** — 飛び先レーンの中にさらに `JUMP` を置いてよい。
  バリエーションのバリエーションが作れる
- **1 本のレーンに複数の `JUMP`** — ただし 1 対 1 なので、それぞれが
  別々の飛び先レーンを持つ

1 対 1 にしたことで、飛び先レーンは必ず 1 つの入口しか持たない。
どの経路で来たかを考えずに済み、`TERM` の戻り先が常に開始元の `CHAN` である
という規則とも噛み合う。

なお、`JDST` レーンどうしが互いを指し合う閉じた輪は、1 対 1 の規則には
違反しないが、どの `CHAN` からも到達できないので鳴ることがない。

**この状態は許容する。エラーとして扱わない。** 鳴らないだけで害が無く、
わざわざ検出して消す動機が無いからである。編集の途中で一時的にこの状態を
通ることもあるし、いま使わない素材を平面上に置いておく作業用の置き場として
意図的に作ることもありうる。到達可能性の検査は行わない。

## 並走レーン

同一チャンネルに `CHAN` 先頭のレーンを複数置くと、**それらは同時に走る**。
分岐シーケンスが「どちらか一方を通る」のに対し、こちらは「両方が同時に流れる」。
同じ `CHAN` を先頭に持つレーンは同じ瞬間に走り出す。

各レーンは自分の `TERM` で自分の `CHAN` へ戻るので、**レーンごとに周期が違ってよい**。
16 ステップのレーンと 4 ステップのレーンを並べれば、後者は前者 1 周のあいだに
4 周する。ここからいくつかの使い方が出てくる。

- **拍によるアクセント制御** — 短いレーンにパラメーターロックだけを置き、
  一定間隔でチャンネルにアクセントを与える
- **ポリリズム的な補助音** — メインと割り切れない長さのレーンにノートを置き、
  周期のずれを利用する
- **メインと異なる長さの補助シーケンス** — 音程の流れとは別の層を重ねる

モックアップのアクセントレーンがこの 1 つ目にあたる。4 ステップのうち 1 番目と
3 番目に `PREL` を置いてあり、ノートを一切持たない。メインレーンが 16 ステップを
1 周するあいだに 4 周し、1 拍おきにチャンネルへアクセントを与える。

このレーンの `PREL` は**自分のスタックの中に掛ける相手を持たない**。掛かるのは
同じ瞬間にそれより後で処理される音——つまりメインレーンやバリエーションレーンの
ノート——になる。**後**は平面上の**下**なので、**アクセントレーンは平面の一番上に
置く**（「Runner」を参照）。

2 本の `CHAN:1` セルは同じ**列**（横位置）に揃えて置いてある。同時に走り出すことが
配置から読めるようにするためで、規則ではない。一方 2 つの **行**（縦位置）が
違うことには意味があり、こちらは実行順を決める。

## Runner

**Runner** はレーンを走査する動的なオブジェクトである。`CHAN` タイルから生まれ、
レール上を右へ移動し、行き当たったタイルを実行して音源部を制御する。譜面が
静的なデータであるのに対し、Runner は **再生時にのみ存在する**。

移動の速さは 2 層で決まる。`Project` が **テンポと拍子**を持ち、`CHAN` が
**1 ステップを何分音符とするか**を持つ（既定は 16 分音符）。前者が全体の時間の
尺度、後者がチャンネルごとの刻みで、両方を掛け合わせて Runner の実速度になる。
**チャンネルごとに刻みを変えられるので、同じテンポの上で速さの違う Runner を
走らせられる。**

`CHAN` レーン 1 本につき Runner が 1 つ生まれる。`JUMP` は新しい Runner を
生まず、既にいる Runner を別のレーンへ移すだけである。したがって
**同時に存在する Runner の数は `CHAN` レーンの本数に等しく、分岐しても増えない**。
並走が Runner を増やし、分岐が Runner の行き先を変える、という分担になる。

### 実行順は `CHAN` の縦位置で決まる

Runner には実行順がある。**それを生んだ `CHAN` タイルが上にあるほど早く、
下にあるほど遅い。**

**この順序は、スタックを上から下へ読むのと同じ流れの続きである。** ある瞬間に
起こることは、平面を上から下へ一度なめる 1 回の走査として処理される。上のレーンの
スタックを上から下まで読み、次に下のレーンのスタックを上から下まで読む。
パラメーターロックが「それより後に処理される音」に掛かるという規則は、
スタックの内側でもレーン間でも同一のものである。

これでアクセントレーンの用法が成り立つ。モックアップではアクセントレーンの
`CHAN` が y=1、メインレーンの `CHAN` が y=3 にある。アクセントの Runner が先に
走って `PREL` でチャンネルの状態を作り、メインの Runner が後からその状態で
ノートを鳴らす。**アクセントを与える側は、対象より上に置かなければならない。**

かつては逆で、**後に実行された側が勝つ**——下の `CHAN` が上の `CHAN` の仕事を
上書きできる——という規則だった。ロックがステップをまたいで残らなくなり、
効果が「以降に処理されるもの」へ流れる形に統一されたので、上書きという概念自体が
無くなっている。同じパラメーターに 2 つのロックが掛かった場合は、後に読まれた
ものが、それ以降の音に対して効く。

順位は Runner に付いて回るのであって、いま走っているレーンの位置ではない。
`JUMP` で飛び先レーンへ移っても順位は生まれ元の `CHAN` のままなので、
**飛び先レーンを平面のどこに置いても実行順は変わらない**。つまり「上から下へ」は
`CHAN` の縦位置についての話であって、スタックが実際に何行目まで伸びているかや、
飛び先レーンがどこに置かれているかは順序に関係しない。

### 同じ高さのレーン

同じ高さに 2 本以上のレーンを置くこともできるが、**推奨しない**。
その場合の実行順は不定とし、実装が任意に決めてよい。上下関係で順位を表す以上、
並んでしまえば決めようが無く、そもそも使いにくい配置である。

## 決定済みの割り切り

### 和音の構成音を区別できるのは、境目より下という形だけ

処理が上から下へ流れるので、`F4 / PREL / G#4 / C5` と書けば `G#4` と `C5` だけが
ロックの影響を受け、`F4` は素のまま鳴る。**和音の構成音に違うパラメーターを与える
ことは、この形でできる。**

できないのは、**間を飛ばして指定すること**である。`G#4` だけを変えて `C5` は素の
ままにする、といった指定はできない。ロックは境目から下すべてに流れるので、
表現できるのは「上のいくつかと下のいくつか」という分割だけであり、
構成音を個別に指名する手段は無い。これは割り切る。

かつては **和音全体に同一のパラメーターが適用される** という、もっと強い割り切り
だった。ロックがどこにあっても直上のノートに付随して見え、実装もステップ内の全
ノートに同じ値を与えていた。上から下への流れに変えたことで、分割までは表現できる
ようになっている。

代替案として「付随セルを横に置く」「従属セルを半セル分インデントしてツリーにする」も
検討したが、前者は横軸＝時間という約束を壊し、後者はグリッドの規則性を失うため採用しなかった。

## 音源側に委ねる事項

音源部分は別プロジェクトとして分離開発している。以下はシーケンサ側では決めず、
結合の段階で確定する。

- パラメーターロックが指せる**対象パラメーターの集合**。音源側が持つ
  （現状 12 個で、`FmPatch` の全フィールドと一致する）
- 変化量の単位と範囲。対象ごとに異なるはずで、対象が決まらないと決まらない

これらはタイルを選択したときの別ウィンドウで設定する。セル上には出さないので、
シーケンサ側の表示設計には影響しない。

**音色はチャンネル単位で持つ。** これも結合の段階で確定した事項である。音源側が
チャンネルぶんのパッチを束ねて持ち、`CHAN` の番号はストリームだけでなく音色も選ぶ。
したがって同じチャンネルの並走レーンは音色を共有し、ロックが常にチャンネル全体に
掛かるという規則とも単位が揃う。分岐レーンは自分の `CHAN` を持たないので、
呼んだ側のチャンネルの音色と刻みで鳴る。チャンネル番号の上限はそのパッチバンクの
大きさで決まる（現状 8）。

**パッチは基準値であって、状態ではない。** ロックはそのステップ限りなので、
チャンネルは毎瞬パッチの値から始まる。演奏中にパッチを書き換えれば次の瞬間から
そのまま効き、ロックが積み上げた何かを打ち消す必要は無い。

**エフェクトはプロジェクト単位、送り量はチャンネル単位。** これも結合の段階で
確定した事項である。リバーブとディレイは譜面全体に 1 つずつで、その設定は
テンポと同じく `Project` が持つ。一方**それぞれへの送り量はパッチの一部**であり、
したがってパラメーターロックの対象でもある。この切り分けがこのシーケンサで
エフェクトを持つ意味そのものである——和音の途中に置いた `PABS` が境目より下の
音だけをリバーブに送り、上の音は素のまま鳴る。エフェクト側の設定をいくら
チャンネルごとに分けても、これは表現できない。

ディレイの時間は**テンポ同期**で、拍に対する音価で指定する。レーンの刻みと同じ
単位だが表は別で、付点を持つ（レーンは小節を割り切る必要があるので持たない）。

## 未決事項

- レーンが自由に置ける以上、レーン数が増えたときに平面のどこに何があるかを
  見失いやすい。整列補助や俯瞰の手段が要るかもしれない
- **周をまたいで少しずつ変化させる手段**。`PACC` の廃止で失った表現である。
  いまは `GCYC` で周ごとに違うステップを通す以外に方法が無い。ロックを
  ステップ限りに縛る決定は覆さないので、必要になったら別の仕組みとして足す
- 複数の `Score` を束ねる必然性。見つかれば `Project` の定義を足す
- 編集操作。タイルを選択すると別ウィンドウが開くことは決めたが、
  タイルの配置・削除・レーンの新規作成をどう操作するかは未定

## モックアップの実装メモ

仕様ではなく `mockup.html` 固有の事情。

- `lanes` の各要素が 1 本のレーン。`x` / `y` が開始位置（グリッド絶対座標）、
  `steps[ステップ][スタック内の位置]` が内容、`head` が先頭セル（`CHAN:n` または
  `JDST`）。スタックの長さはステップごとに違ってよい。
  `TERM` は最終ステップの右隣に自動で置かれる。配列の順序は描画順にすぎないが、
  仕様側では縦位置が実行順を決めるので、読みやすさのため `y` の昇順に並べてある
- ジャンプは `JDST` レーン側の `from` が持つ。そこに書くのは `JUMP` セルの座標
  だけで、着地点はそのレーンの `head` 位置から導出する。**`JUMP` が `JDST` 以外に
  着地することも、1 つの `JDST` が 2 つの `JUMP` を持つことも、書きようがない。**
  かつては独立した `links` 配列に持たせていたが、1 対 1 を規則ではなく構造で
  保証するため飛び先レーンの属性に移した
- 値の先頭に `*` を付けると白塗り潰しのセルになる
- 縦の連結線は「真上のセルが埋まっているか」だけで引いている。レーンを自由に
  置ける以上、あるレーンのスタックの末尾と別のレーンの先頭が縦に隣り合うと
  無関係な 2 つが繋がって見える。現在の配置では間を 1 行空けて避けているが、
  配置の制約として持たせるか、レーンの所属を見て引くかは決めていない
- アイコンは 15×15 の viewBox で、線幅 1px、座標は半整数に揃えてある。
  1px ストロークの中心を画素境界に乗せて滲みを防ぐためで、`cycle()` / `prob()` の
  線幅とも一致させている。ジャンプ線のオフセットが 7.5px という半端な値なのも同じ理由
- 描画関数の名前は 2 系統ある。部品として使い回すものは形状に由来し
  （`fader` / `chevron` / `arrowHead` / `line`）、特定のタイル 1 種を
  描くものはその役割に由来する（`cycle` / `prob` / `uTurn` / `zigzag` / `entry`）。
  後者のうち `cycle()` / `prob()` はかつて `bits()` / `pie()` という形状名だったが、
  形が変われば嘘になる名前だったので役割名に改めた
- `PACC` の廃止に伴って、その Δ を描いていた `delta()` と、それだけが使っていた
  `poly()` / `lineCross()` も消した。`PREL` のアイコンは `PACC` と並ぶことを
  前提にフェーダーを左に寄せた配置だが、2 種になっても `PABS` との区別は付くので
  そのままにしている
- ジャンプ線は SVG レイヤ（`.links`）に描く。角を丸めるため。`roundedPath()` が
  点列から角丸パスを生成する。レールの点線は今も div の
  `repeating-linear-gradient` で描いており、2 つの方式が混在している
